# 設備驗收接續順序

2026-11-26 已完成 Orin NX 的 `NX_LEGACY_BOUNDED_CPU_ACCEPT_LIMITED`。單次推論 4.969 秒，受限 slice 樣本最大值 708,984,832 bytes，精確峰值為 `null`。原 R1 精確模式與其單次資格仍保留。參考 [Legacy Kernel 契約](LEGACY-KERNEL-MEMORY.md)及[原始 NX 操作契約](LEGACY-NX-RUNBOOK.md)。NX 端 GNU tar 相容性解封只使用 `--keep-old-files`（保留排他建立與完整逐檔核對）。

本輪只做隔離準備與已授權的唯讀盤點。下一階段各自固定版本、設備、批准窗口、來源、工作和回收證據。H3 新的 bounded CPU 資格需要將記憶體模式及主機回復權威一起釘選，沿用前次證據須限於 CPU 能力前置。

Windows P2 Owner 10/10、Peer 5/5，以及 RC2-R3 離線 ARM64 真實 JSON／SSE 已通過，直接沿用，不再建立測試帳號或重跑。唯讀遙測、H3、GPU 與部署各自的邊界見 [H2-LIVE-TELEMETRY.md](H2-LIVE-TELEMETRY.md)、[CROSS-HOST-ADMISSION.md](CROSS-HOST-ADMISSION.md)、[GPU-ADMISSION.md](GPU-ADMISSION.md)、[PRODUCTION-CUTOVER.md](PRODUCTION-CUTOVER.md)。

逐項保存版本、設備身分、操作者批准、時間窗、開始狀態、測試輸出、停止狀態及回復證據。某項 HOLD 時保留原設備和資料。每個步驟的權限以當次授權為準。

| 順序 | 啟動前核對 | 驗收及停止條件 |
|---|---|---|
| 1. NX Legacy CPU | 完成。沿用已封存的單次實機證據 | 原 R1 精確峰值資格獨立保留，須具備 `memory.peak` 才能另行啟動 |
| 2. 真實唯讀 | H2 同一可信管理程序的接入已完成。跨 SID 資料管道需另核入口、scope 與生命週期 | 身分失配、撤銷、過期及清單語意逐項核對，純讀取 |
| 3. 跨主機 Worker／API | 先完成回復權威隔離、服務端 SSH 專用限制及零生成握手。各端固定來源、相同時間契約、獨立實體鎖及操作窗口 | 取得當次批准後，JSON 和 SSE 各以自己的新窗口與一次資格驗收。斷線／取消後終態不明時保留 HOLD |
| 4. GPU | 先取得獨立執行域、資產閉包、可強制的 GPU 硬限額、分配歸屬及回收權威證據 | 關鍵證據缺失即拒絕派送。回收證據失效時保留資源鎖 |
| 5. 多節點 | 各設備與模型獨立合格，先確認產品能同時持有兩個分離的 Worker 資格 | 兩個執行域同時分別持鎖。一台斷線持鎖且原 attempt 不重送，健康節點原工作完成 |
| 6. 正式部署與回滾 | 分別取得切換及回滾批准，核對來源、祖先 ACL、持有者、具名埠、冷備份及資料 lineage | 依操作入口向新位置演練，正常停止與 rollback 皆保留源資料；分岔保留兩邊，不原地覆蓋 |
| 7. GitHub 發布 | 權利人確認授權及同意發佈，核對乾淨來源、TAR、SBOM 與私密掃描 | 這階段只產出本機候選 |

## RC2-R3 與實機准入

RC2-R3 的引擎驗收在離線 ARM64 客體使用獨立 SQLite、單次資格及合成測試輸入。實機窗口另核對實體身分、正式資料隔離及恢復基準。標準 Windows 帳號已在原生主機完成 P2；保留實際標準 SID、完整祖先安全、junction 與替換拒絕、備份、升級、還原的獨立回條，不將同主機資格擴張為任意其他 Windows 主機合格。

工作提交前核對指定引擎程序、匿名標準 I/O 對端、受限資源以及可信簽章。取得同次 CPU runner、峰值、限額、引擎退出及暫態單元回收的證據後，由可信觀測者先核對 R1 持久提交，再核對產品資源鎖提交。非串流成功回應與 SSE 終態均須晚於這兩次提交。若啟動、終態、限額或回收證據不全，保留原工作與鎖。一次性資格由新窗口發行，歷史 HOLD 不重送。
