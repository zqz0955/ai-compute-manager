# 真實唯讀監控接入驗收

本次工具使用既有受保護觀測器，透過 V0.6 固定本機 GET 取得資料，再交給 V1.0 既有簽章遙測介面。它是本機驗收工具，不是新的正式服務或持續派送授權。

## 信任鏈

1. 管理端核對原觀測器的受審清單摘要及完整 15 檔的內容 SHA／物件身分，包括投影模組依賴的 `acm-api.mjs`；每次來源核對均重新檢查完整清單。檔名只允許單層 `.mjs`／`.ps1`／`.py`，拒絕路徑跳脫、資料流與其他副檔名。Python runtime 另以原受保護設定中的摘要核對。
2. 原生查核固定 V0.6 執行身分、PID、建立時間、Node、唯讀命令列、唯一 IPv4 loopback 監聽者及 588 檔 SHA。每條 HTTP 連線再查 Windows TCP 擁有者。來源程序重啟須重新建立本次工作階段，不能沿用舊身分摘要。
3. 僅呼叫原觀測器允許的 GET。未接入有刪除副作用風險的舊版 `/api/history`。不轉送 Token、提示詞或模型回答，不讀正式 SQLite 或 SSH 私鑰。
4. 原始回應先經原投影器及 V1.0 `projectLegacyTelemetry` 驗證。簽章綁定來源身分、節點、當輪 challenge 及原採樣時間。來源身分在簽署前後均重新核對。
5. 既有 relay 用獨立金鑰與持久序號簽署，經既有 `/acm/v1/telemetry/challenge`、`/acm/v1/telemetry/snapshot` 接入。兩個發送者分別綁定兩台設備，不能交叉發布或使用讀取權限冒充發送權限。
6. V1.0 在獨立資料根、動態 loopback 埠執行 `read-only`。同時保留 Windows 真實 CPU、RAM 與磁碟採樣。此驗收沒有直接連線設備的 SSH，也不更動原觀測器。

## 執行

使用已核對的 Windows Node 24.22.3。先依原手動入口啟動通過來源／ACL 核對的 V0.6，然後在已授權的私有測試工作區執行。

```text
node tools/h2-live-telemetry.mjs <既有受保護觀測器根目錄> <新的私有驗收目錄> <新的回條檔案>
```

原核可觀測器路徑、來源 IP 及帳號資料由本機參數與受保護設定取得，沒有新增至公開產品設定。此工具鎖定現有受審來源清單 SHA。未符來源時直接停止，不能以另一個同名工具取代。

Windows 工作區 fixture 只能使用原產品的 `ACM_TEST_ROOT` 與 `ACM_INSTALL_WORKSPACE_FIXTURE` 明確邊界。這項隔離驗收不重新授予正式安裝資格。原 P2 標準帳號原生證據獨立保留。

## 原生驗收內容

- 兩輪真實 A／NX 採樣與 V1.0 Dashboard JSON 逐欄對照，保留 CPU／GPU 零值及原時間。
- 模型查詢失敗為 `null/UNKNOWN`，有效空駐留清單為 `[]/VALID`，兩者不得混用。
- 原生 Windows 本機採樣與兩個設備同時出現在唯讀 Dashboard。
- 發送 scope、跨節點發布、同一 challenge 重播及錯誤 challenge 拒絕。
- 來源身分遺失採用注入反例；不停止或破壞正式 V0.6。停止本次轉送後實際等待超過 15 秒，確認數值、模型與駐留清單變成 UNKNOWN／null，仍保留原採樣時間。
- 新工作數與資源預留均為零。持有 `models:run` 仍無法從唯讀候選派送推論。
- 本次可留下最長五分鐘的本機瀏覽器驗收窗口，`ui-access.json` 的暫時讀取 Token 只供該工作階段，禁止納入公開或審查封包。寫入 `ui-done.json` 的 `{"done":true}` 提前結束；正常收尾停止隔離服務並撤銷所有測試 Token。
- 最終工具的關閉、逐一 Token 撤銷與暫時檔移除各自保存結果；任一步驟失敗皆保留 HOLD，仍嘗試保存安全化回條。僅關閉已確認成功才標記 `isolatedServiceStopped=true`，不強制終止程序；回條本身無法保存時明確回報 `H2_RECEIPT_WRITE_FAILED`。
- `h2-dashboard.mjs` 在既有本機 Chrome 中直接讀取暫時憑證，驗證三台實際節點、來源標籤、模型與有效空駐留清單、唯讀拒絕及清除頁面憑證。瀏覽器只允許該次動態 loopback origin，獨立 profile 留在本次測試目錄。回條不記錄憑證。瀏覽器關閉失敗仍送出隔離服務收尾訊號並保存 HOLD；訊號失敗亦保存 HOLD，回條寫入失敗以固定錯誤碼明確退出。此失敗路徑另以純記憶體故障注入核對，沒有重跑真實設備採樣。
- 兩個節點各有獨立的 challenge 與持久 signer，核對及簽署並行進行。初次環境缺漏及後續兩次安全拒絕回條皆保留；其中第一個 ERR_ASSERTION 沒有足夠位置診斷，根因仍為 UNKNOWN。第二次已定位第二台發布拒絕，串列處理消耗新鮮度為時序證據支持的推論；產品只公開 TELEMETRY_REJECTED，未將該推論寫成內部直接拒絕原因。最終並行驗收逐筆記錄原時間與發布年齡，沒有延長產品 15 秒新鮮度或重寫來源時間。遇相同樣本直接跳過發布，不能用新序號重新包裝成新鮮採樣。

## H5 資格限制

本次三台設備的資料可以用於唯讀能力比較，所有真實觀測節點仍為 `availability=UNVERIFIED`。尚未取得相應 Worker／模型／執行模式資格時，沒有可分配的真實執行節點，也不建立推論資源預留。

最後受影響複驗同時檢查新增的 Dashboard `placement` 唯讀准入診斷：三台真實節點各自列出 `READ_ONLY_MODE` 與 `OBSERVATION_NOT_EXECUTION_QUALIFICATION`，選擇結果為空集、無預留與派送。API 過期驗收另核對 `TELEMETRY_STALE`；實際 Chrome 驗收的是恢復新鮮採樣後的三台唯讀拒絕理由，未在瀏覽器重播過期畫面。這項診斷不執行資源配置、佇列、優先級或 Worker 資格評估。

既有模擬佇列、優先級、排他鎖與資格 Worker 不因這次真實遙測接入而自動取得多節點實機派送資格。H5 的真實推論、預留與故障復原驗收須分開完成。此工具不把唯讀排除結果宣稱為多節點模型運算通過。

## 證據邊界

本次使用既有 V0.7 發行目錄中的可信 V0.6 原生觀測工具，但沒有改動或重新驗收 V0.7 的命名管道服務。直接 V0.6 觀測鏈與 V0.7 管道資格應分別記錄。原生設備斷線、服務重新啟動及權限變更沒有在既有設備上注入。

本輪 V1.0 隔離 API 與簽章觀測器在同一個可信管理端 Node 程序內執行；回條記錄其實際 Windows SID 及兩者 PID 相同的關係。這可驗證真實來源、簽章、API、資料語意與介面，但不能代替 `AIComputeApiRunner` 跨 SID、命名管道或長期服務的部署隔離驗收。那些資格僅沿用歷史證據，未在本輪重驗。

回條只記錄來源摘要、程序世代、已投影的資源值、查詢狀態與拒絕結果。私有測試目錄保存的暫時金鑰與權杖不屬於可公開證據。
