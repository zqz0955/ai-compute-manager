# 架構、狀態及資料流

~~~mermaid
flowchart LR
    Browser[本機 Dashboard] --> API[固定 IPv4 loopback API]
    Client[本機應用] --> API
    API --> Auth[憑證雜湊、有效期、Scope]
    Auth --> Views[節點、工作、監控、歷史投影]
    Auth --> Controller[持久化工作與調度]
    Controller --> DB[(SQLite 工作與資源)]
    Controller --> Sim[隔離合成 Worker]
    Sim --> Evidence[簽章終態與新鮮資源證據]
    Evidence --> Controller
    Views --> History[(本機採樣與版本歷史快照)]
    Capsule[R1 隔離真實引擎介面] -. 獨立操作資格 .-> Real[受控 Worker 與 Ollama]
~~~

## 工作狀態

1. 驗證請求方、請求識別、模型摘要、Context 及參數後，先持久化 QUEUED。相同客戶端、請求識別及內容重新查詢同一份工作。只允許明確新增的工作使用其他節點。
2. 從合格候選挑選節點。CPU、GPU、RAM、磁碟、模型及健康均需符合模式下的資格。合成節點的環境與實體身分均由隔離測試資料提供。相同實體或有重疊別名的節點占用同一把鎖。鎖及派送意圖先提交，再完成啟動。
3. RUNNING 的取消進入 STOPPING，等待終態及清空證據。客戶端 HTTP 中斷只解除等待。OOM、逾時、斷線或不明終態依證據分類。
4. 簽章、工作識別、資源、世代、模型與新鮮空閒證據成立後才提交終態及釋放。證據不完整保持 HOLD。重啟不重送原工作。
5. R1 真實引擎保留一發、短時間窗口、Worker 身分與原子回復確認。R1 adapter 不接公共 HTTP 或一般排程。真實環境另需核對引擎、裝置、端點、模型、主機回復及部署資產。

## 資料與限制

- controller.sqlite 保存工作、選擇原因、別名、鎖與簽章事件。SQLite FULL/WAL 及安裝鎖限定單一寫入者。工作摘要不暴露模型輸入或輸出，合格擁有者可取得自己已完成的結果。
- telemetry.sqlite 保存真實唯讀和合成採樣及來源，上限 20,000 筆。監控查詢不刪除資料。缺欄位用 null，來源不明使用 UNKNOWN，過期使用 STALE，數值 0 代表已知零值。
- history archive 是明確匯入的舊版本投影。歷史工作從未放入此次佇列。
- 獨立節點並行各執行一份工作。產品未驗收單一模型跨設備切分、GPU 真實記憶體回收或跨平台遠端復原。
- 後續私人遠端設計應使用另外核准、具相互認證的閘道，固定設備身分及明確操作 scope。連線身分、排程資格及持久化鎖在跨主機前均須重新核對。

## RC2 真實唯讀資料與引擎准入

Windows 本機採樣、Linux ARM64 Agent 及 V0.6／V0.7 可信觀測器資料分開標示。簽章發送者只可處理綁定 public key 的 nodeId。一次性 challenge、原採樣時間與持久序號共同限制回放。序號更新和採樣寫入同一交易，舊版資料仍可回讀。Dashboard 會合併顯示已核對的觀測資料，排程仍取自隔離控制器的合格能力及資源鎖。

一般服務僅接受 read-only 與 simulation 配置。真實引擎候選的程式入口另需以管理者信任根核對短效一發資格，綁定資料庫實物身分、模型摘要、資源、引擎與 Worker 世代。R1 單次實機資格與這份隔離程式的授權網域獨立。證據不足或驗證失敗維持資源封鎖，沒有由監控資料或配置自動放行的路徑。

即時 SSE 可在執行期間送出有 provisional 標記的片段。正式用量、finish_reason 與 [DONE] 都等同次終態及資源證據提交後才送。取消、失聯、遺失或證據矛盾保留原工作，後續由有權限的客戶端查狀態。
