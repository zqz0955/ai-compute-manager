裝置與資源

初次設定

建立本機讀取權限，選擇模擬或讀取已核對的監控來源。

本機試用

  1. 從已核對的候選目錄執行 node tools/rc.mjs setup <新安裝目錄>。
  2. 加入 --monitor-local 讀取 Windows 本機資源，或加入 --simulation 試跑合成工作。
  3. 以 node tools/rc.mjs token issue <安裝目錄> viewer manage:read 簽發讀取憑證。
  4. 使用手動啟動器。本頁輸入讀取憑證，模擬派送另需 models:run。

準備唯讀節點註冊

向設備操作人取得 Agent 公鑰及節點識別。保存下方設定片段供本機管理員核對。

註冊需核對發送者及公鑰。節點資料保持唯讀。

          Dashboard API
          
        
          以下路徑同源，憑證使用 Authorization: Bearer，取消須具備工作的擁有者權限。
          
        
          
          
          
            
          方法與路徑權限用途
          
            
              
          GET /acm/v1/dashboardmanage:read總覽、工作、資源鎖與診斷
          
              
          GET /acm/v1/dashboard/history?nodeId=…manage:read讀取節點採樣
          
              
          POST /acm/v1/telemetry/challenge
          POST /acm/v1/telemetry/snapshot          		telemetry:publish發送固定節點的簽章遙測
          
              
          POST /acm/v1/jobsmodels:run建立非同步測試工作
          
              
          GET /acm/v1/jobs/:idmanage:read 或建立者的 models:run檢視狀態與允許查看的輸出
          
              
          POST /acm/v1/jobs/:id/cancel建立者的 models:run要求取消，後續以工作狀態為準
          
                      
          
          
        
          
        
          
          其他 API 介面與憑證維護
          
          既有唯讀管理介面沿用 /acm/v1 的健康狀態、節點、歷史與任務路徑，讀取需要 manage:read。
          
          
          OpenAI 相容介面提供 GET /v1/models、POST /v1/chat/completions 與 POST /v1/completions。模型執行需要 models:run，本候選只允許離線模擬推論。
          
          
          manage:write 保留給本機維護流程。關閉自行啟動的這一版候選後，在候選程式目錄執行憑證維護命令。輪替沿用原權限，撤銷的識別碼不得重用。
          
          
            
            
          • node tools/rc.mjs token issue <安裝目錄絕對路徑> <id> <scope[,scope...]> [ttl-hours=24]

          • node tools/rc.mjs token rotate <安裝目錄絕對路徑> <id> [ttl-hours=24]
            • 
            
          • node tools/rc.mjs token revoke <安裝目錄絕對路徑> <id>
